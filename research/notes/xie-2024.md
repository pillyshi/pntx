# xie-2024

## Citation

Xie, C., Lin, Z., Backurs, A., Gopi, S., Yu, D., Inan, H., Nori, H., Jiang,
H., Zhang, H., Lee, Y. T., Li, B., & Yekhanin, S. (2024). *Differentially
Private Synthetic Data via Foundation Model APIs 2: Text.* ICML 2024 (PMLR
235). arXiv:2403.01749 (DOI 10.48550/arxiv.2403.01749).

## Why It Matters For This Project

`pn2t.SyntheticSampler` targets the same use case as this paper: release a
synthetic stand-in for a private text pool, using only LLM *inference* (no
fine-tuning), which matches pntx's llama.cpp-in-process setup. Aug-PE is the
closest method that comes with a *formal* (ε, δ)-DP guarantee. It is the
reference point for what SyntheticSampler's best-effort anonymisation
(prompt instructions + `contains_verbatim_span`) does **not** provide.

## Method

Augmented Private Evolution (Aug-PE), extending PE (Lin et al., 2024) from
images to text:

1. `RANDOM_API`: prompt the LLM for samples using only the (assumed
   non-private) class label, diversified by randomly sampled sub-category
   keywords ("pseudo-classes").
2. Repeat for T iterations:
   - Embed private and synthetic samples with a sentence-transformer `Φ`.
   - `DP_NN_HISTOGRAM`: each private sample votes for its nearest synthetic
     sample; add Gaussian noise `N(0, σ²)` to each bin (sensitivity 1).
   - Keep the top-`N_syn` synthetic samples by noisy vote (rank-based, not
     random resampling, to avoid duplicates).
   - `VARIATION_API`: generate `L−1` variations of each kept sample by
     paraphrase or fill-in-the-blanks prompts, with random tone phrases and
     a target word count (adaptive length).
3. Privacy is tracked with adaptive DP composition across iterations.

The key structural property is that **private texts are never put in an LLM
prompt**. They only influence the output through noisy nearest-neighbour
votes in embedding space, and DP follows by post-processing.

## Relevant Findings

- With the same GPT-2-series generators and ε ∈ {4, 2, 1}, Aug-PE matches
  DP-fine-tuned generators (Yue et al. 2023, [[yue-2023]]) on downstream
  accuracy, and beats them in some settings. With GPT-3.5 or modern open
  7B-class LLMs, utility improves further, especially on the domain-heavy
  OpenReview and PubMed sets.
- More robust to DP noise in some cases (OpenReview rating with GPT-3.5:
  45.4 → 43.1 from ε = ∞ to 1, vs DP-FT generator 48.3 → 38.6).
- Downstream models trained on Aug-PE data show lower membership-inference
  AUC (PPL, REFER, LiRA) than DP fine-tuning baselines on PubMed.
- Far cheaper than DP-SGD fine-tuning (12.7×–65.7× speedup in GPU hours for
  100k Yelp samples).
- Ablations: initial samples *without* private-data voting have limited
  utility, so the private signal is doing real work. Rank-based selection
  beats original PE's random resampling.
- Even at ε = ∞, Aug-PE does not fully recover the real-data distribution
  (gap to training on original data remains).

## Limitations

- Class labels are assumed non-private.
- Needs many private samples for the vote histogram to carry signal (datasets
  here have thousands to millions); utility with tens of private examples,
  a common pntx scale, is untested.
- Costly in calls: Nsyn·L generations per iteration over T iterations, plus
  embeddings. Measured in GPU-hours, not seconds.
- Requires an embedding model (`pntx[embeddings]` is optional today).
- Synthetic data still diverges from real data even without noise.

## Actionable Findings

1. **Be explicit that SyntheticSampler is not DP.** It puts private positive
   exemplars directly into the prompt, and its safeguards are best effort
   (instructions plus verbatim-span rejection). Aug-PE shows that a formal
   guarantee requires keeping private text *out* of the prompt entirely.
   README/docstring should name this trade-off and point to Aug-PE/DP
   methods for users who need guarantees.
2. **Possible future DP mode.** Aug-PE maps cleanly onto existing pntx
   pieces: `Backend.complete` (RANDOM/VARIATION APIs, no fine-tuning needed,
   so it works with `LlamaCppBackend`), `pntx[embeddings]` for `Φ`, and the
   sklearn sampler API. A `DPSyntheticSampler` (or a `privacy="dp"` design
   alternative) is feasible but would be a separate class with an ε/δ
   accountant. CLAUDE.md scopes SyntheticSampler's privacy to best-effort
   verbatim-copy detection, so this would need an explicit scope decision.
3. **Cheap wins without DP.** Two Aug-PE generation tricks transfer directly
   to SyntheticSampler's diversity problem: pseudo-class / sub-category
   keywords sampled per batch, and random tone phrases. The adaptive target
   word count (with noise) addresses length-distribution mismatch.
4. **Evaluation protocol.** Aug-PE's protocol (train a downstream classifier
   on synthetic data, test on real data, plus embedding-distribution
   metrics such as FID/MAUVE and membership inference AUC) is a good
   template for a SyntheticSampler benchmark.

## Issue Candidate Impact

- Docs fix: state the non-DP nature of SyntheticSampler explicitly (item 1).
- Idea candidate: diversity knobs for SyntheticSampler (item 3), which is

- Idea candidate: SyntheticSampler benchmark using the Aug-PE protocol
